プライバシーポリシー

Google Driveのデータを、何のために取得し、どこで処理・保存するかを説明します。

制定・最終更新日：2026年11月2日

本ポリシーは、ike-takuが個人開発・運営する「Paper-to-Podcast」の現行実装と、この公開説明サイトに適用します。本アプリは、利用者が自身のPCとGoogleアカウントで利用する研究・学習支援ツールです。

1. 取得・生成するデータ

  • 設定したDriveフォルダ内のファイル一覧とメタデータ（ファイル名、パス、ファイルID、サイズ、更新日時、フォルダ情報など）。
  • 処理対象のPDFファイルと、その本文・ページ別テキスト。PDFに個人情報が含まれる場合、その情報も処理対象になり得ます。
  • PDFから作成する原文抜粋・根拠、要約、日本語対話台本、発話音声、MP3、処理時間・音声長などの指標、完了情報。
  • 重複判定のためのファイルハッシュ、処理状態・試行回数、元ファイル名、処理履歴・エラー情報。
  • Google Drive接続のためにrcloneが取得・管理するOAuthアクセストークンと更新トークン。

本アプリはGmail、連絡先、カレンダーのデータを取得しません。Googleアカウントのパスワードをアプリへ入力する仕組みはありません。

2. Driveの権限と対象範囲

スマートフォンや他のアプリが保存したPDFを取得し、生成物を保存するため、Google Driveの通常の読み書き権限（https://www.googleapis.com/auth/drive）をrcloneで設定する構成です。

このOAuth権限は、設定フォルダだけに限定された権限ではありません。認可されたGoogleアカウントのDriveファイルに広くアクセスできる権限です。

アプリの通常処理は、利用者が指定したベースフォルダのInbox、Processing、Output、Failedと、その配下を対象にします。Inbox直下のPDFを処理し、必要に応じて設定フォルダの一覧・状態を確認します。フォルダ設定による処理範囲と、OAuth権限の範囲は異なります。

3. 利用目的と処理の流れ

  1. Inboxを定期確認し、変更が安定したPDFをローカルPCへ取得します。
  2. ファイルハッシュとSQLiteの処理キューで、重複処理と再試行を管理します。
  3. PC上でPDFのテキストを抽出し、同じPCのLLMへ本文・抜粋・台本を渡して、日本語要約と対話を生成・監査します。
  4. 同じPCのCPU上でKokoroによる音声を生成し、FFmpegでMP3へ変換します。
  5. MP3、要約、台本、指標、元ファイル情報、完了情報をDriveのOutputへ保存します。ProcessingにはPDFのコピーを保存し、最終失敗時はFailedへのエラー情報送信を試みます。

データは、これらの利用者向け機能と、その処理の再開・重複防止・障害確認のために使用します。個人向けの中央収集サーバーへデータを集める仕組みはありません。

4. 保存先と保存期間

  • ローカルPC：PDFコピー、ページ別本文、根拠と抜粋、章別台本、発話音声、MP3、要約、処理キュー、再開用ファイル、検証失敗の診断ファイル、エラー・運用ログを保存します。診断ファイルには生成途中の台本や原文抜粋が含まれる場合があります。
  • Google Drive：Inboxの原本を残し、ProcessingにPDFコピー、Outputに生成物と元ファイル名などの情報、Failedに送信できた失敗情報を保存します。
  • OAuth認証情報：rcloneの設定ファイルにローカル保存されます。保存場所は利用者のrclone設定によって異なります。

アプリには保存期限を定めた自動削除機能がありません。データは利用者が削除するまで残ります。一時ダウンロードファイルやMP3変換後の結合用WAVは処理の一部として削除しますが、これにより保存済みPDF・発話クリップ・台本・生成物がすべて削除されるわけではありません。

利用者が別途作成したバックアップ、端末へのダウンロード、OSやサービス側の履歴にもコピーが残る場合があります。

5. 第三者提供・外部サービスへの送信

本アプリの機能として、Googleユーザーデータや生成物を販売したり、広告事業者・データ仲介業者などへ提供したりしません。クラウドLLM・TTS APIへPDF本文、抜粋、台本、音声を送信する処理はありません。

Google Driveへの取得・保存・認証では、利用者が認可したGoogleとの間でデータを送受信します。Drive上の既存の共有設定によっては、保存したファイルを共有相手が閲覧できます。アプリは共有設定を自動で非公開へ変更しません。Google側の取り扱いにはGoogleのプライバシーポリシーが適用されます。

初回導入やモデル・日本語辞書の取得時には、パッケージ配布元やモデル配布元へのネットワーク接続が必要です。これらのダウンロードは、論文データを送ってクラウド推論を行うものではありません。

6. Google API Services User Data Policy・Limited Use・AI利用

Paper-to-PodcastによるGoogle APIから受け取った情報の利用、および他のアプリへの転送は、Limited Use要件を含むGoogle API Services User Data Policyに従います。

  • Googleユーザーデータは、本ポリシーで説明したPDFの取得、ローカルの要約・音声生成、結果の保存と処理管理に使用します。
  • Googleユーザーデータおよびその派生データを、汎用AI・機械学習モデルの学習や追加学習に使用しません。LLMとTTSは、要約・台本・音声を生成する推論にのみ使用します。
  • 広告配信、販売、信用評価・融資判断、利用目的と無関係な分析に使用しません。
  • 利用者自身が管理するPCとDriveで原文・出力を確認する構成です。運営者が他の利用者のデータを中央で収集・閲覧する機能はありません。個別データのサポート確認が必要な場合は、その対象と目的を説明し、明示的な同意なく閲覧を求めません。

7. データの削除・アクセス取り消し・利用停止

  1. まずPC上のworkerを停止し、新しいダウンロードや再生成を止めます。
  2. DriveのInbox、Processing、Output、Failedから不要なファイルを利用者が手動で削除します。InboxにPDFを残したままローカル履歴を消すと、再取得・再生成される場合があります。
  3. ローカルの設定済みデータディレクトリからPDF、テキスト、音声、キュー、再開・診断・失敗ファイルを削除します。運用ログ、バックアップ、他の端末のコピーも必要に応じて別途削除します。
  4. Googleアカウントの接続管理で本アプリのアクセス権を取り消し、不要なrclone認証設定も削除します。

アクセス権の取り消しだけでは、すでに保存したデータは削除されません。Driveとローカルの片方で削除しても、もう片方のコピーは削除されません。Driveのゴミ箱・版履歴やバックアップはそれぞれの仕様・設定に従って管理してください。アプリには一括削除画面や、復元不能な消去を保証する機能はありません。

8. 安全管理の実装範囲

LLM接続先はHTTPのループバックアドレスに制限し、クラウド推論への自動フォールバックを行いません。推論処理は利用者自身のPCで行い、通常の運用ではOAuth認証情報を公開ページやコードリポジトリに含めません。

アプリ独自の保存時暗号化、独自の認証基盤、利用者別のアクセス制御画面、定期的な自動削除は実装していません。ローカル保存先の保護は、PCのOS権限、ディスク設定、アカウント管理に依存します。Google Driveの共有範囲、PCのアクセス権、認証設定の保管は利用者が管理してください。

9. この公開Webサイトについて

このサイトはGitHub Pages上の静的な説明ページです。サイト自体にはGoogleログイン、PDFアップロード、問い合わせフォーム、アクセス解析、広告、外部フォント、Cookieを設定するスクリプトを設置していません。DriveのPDFや認証情報をこのサイトへ送る仕組みはありません。

ページの配信に伴い、ホスティング提供元のGitHubがIPアドレスなどのアクセス情報を処理する場合があります。詳しくはGitHubのプライバシーに関する声明をご確認ください。外部リンク先では各サービスの方針が適用されます。
